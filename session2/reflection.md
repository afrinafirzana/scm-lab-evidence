# Session 2 Reflection

## Q1: How do Issues and pull requests together support change control?

From this activity, I learned that Issues are used to explain why a change is needed and what needs to be completed. Pull requests allow the changes to be a reviewed before they are merged into the main branch. By linking an Issue to a pull request, it becomes easier to track the progress of a change. This also helps team members understand why a particular change was made.

## Q2: Why did the conflict in Part 4 happen, and how could a team reduce such conflicts?

The conflict happened because branch-a and branch-b made different changes to the same line in the same file. Git could not decide which change to keep, so I had to resolve it manually. I resolved the conflict by combining both changes into one suitable statement. To reduce merge conflicts, team members should communicate with each other and regularly update their branches.

## Q3: What would be lost if people merged straight into main without a pull request?

If team members merged their changes directly into main, they would lose the opportunity to review the changes beforehand. Mistakes or unwanted changes might go unnoticed and affect the project. It would also be harder to understand why certain changes were made without proper review discussions. Therefore, pull requests help maintain software quality and accountability.
